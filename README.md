# Mini GRC Compliance Tracker

## Project Overview

This beginner portfolio project demonstrates foundational Governance, Risk, and Compliance (GRC) concepts through a simulated compliance monitoring workflow.

## Objective

Track sample security controls, supporting evidence, control status, and remediation activities using a simple manual process inspired by common compliance automation workflows.

## Framework Alignment

Sample controls are loosely aligned with concepts found in SOC 2 and ISO/IEC 27001.

This is an educational exercise, not an official audit, certification, or assessment of a real organization.

## Project Components

- Control Register: Tracks control IDs, requirements, status, and evidence.
- Remediation Log: Records sample findings, risks, corrective actions, and status.
- Evidence Register: Documents supporting evidence, collection dates, review status, and reviewer notes.

 ## Project Workflow

1. Identify and document security controls in the Control Register.
2. Record supporting evidence in the Evidence Register.
3. Identify control gaps and document findings in the Remediation Log.
4. Assign corrective actions and monitor remediation progress.
5. Review supporting evidence to determine whether findings can be closed.

## Skills Demonstrated

- Security control monitoring
- Evidence tracking and documentation
- Risk identification
- Remediation tracking
- Audit-readiness concepts
- Foundational GRC workflows

  ## Project Results

The simulated compliance review included five security controls across access control, vulnerability management, incident response, and security awareness.

Key results:

- Documented five sample security controls and their operating status.
- Identified two findings requiring corrective action.
- Assigned risk levels, responsible owners, and target completion dates.
- Created five supporting evidence records linked to their respective controls.
- Identified outstanding remediation and evidence review activities.
- Cross-checked the control register, remediation log, and evidence register for consistency.

## Lessons Learned

Through this project, I practiced:

- Documenting security controls and monitoring their status.
- Connecting control requirements to supporting evidence.
- Identifying gaps and documenting associated risks.
- Tracking corrective actions and remediation progress.
- Reviewing evidence and identifying outstanding verification requirements.
- Maintaining consistency and traceability across GRC documentation.

This exercise reinforced the importance of evidence-based control monitoring and ongoing remediation tracking.
